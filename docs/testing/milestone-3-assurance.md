## Findings and open exercises

- The local public-bootstrap measurement failed its 500 ms p95 budget: median 1775.2 ms, p95 10499.5 ms. This local Worker had no edge KV binding and queried the remote development database; this is a failed measurement, not staging performance evidence. Repeat against a deployed staging Worker with KV and representative tenants.
- A successful Paystack payment still requires completing one test checkout using Paystack's test card, then retaining API, webhook, invoice, and receipt evidence.
- Supabase Auth sends staff invitation mail. Code now sets the portal invitation redirect, provides a password-setting screen, and activates an invited membership only after the invited authenticated user returns. Delivery evidence still requires a controlled mailbox.
- Database PITR, storage restore, deployment rollback, queue replay, and domain restoration must run against a disposable staging environment. They must not be simulated against the only hosted development database.
- Large-data and concurrency testing needs an agreed capacity model and a disposable staging dataset.
- The old system was explicitly excluded from this greenfield database. Legacy comparison requires access to a running legacy environment or approved exported fixtures.
- Pilot approval is a human acceptance decision from the selected school and cannot be generated by an automated test.
